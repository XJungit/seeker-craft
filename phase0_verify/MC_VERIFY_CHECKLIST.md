### 1. enigo 能否驱动 MC 视角旋转 ✅ **通过**
- [x] 开 Minecraft（**窗口化、固定分辨率**，如 1280×720）
- [x] 进一个创造/生存世界，站定，鼠标自由（不锁定点）
- [x] 运行 `enigo_mc_test`，选 "view" 模式

- ~~若不转 → 退回 windows crate SendInput~~ （无需执行）
- **结论**：enigo 0.6.1 的 `Mouse::move_mouse(dx,dy,Rel)` 可直接驱动 MC 原始输入视角旋转

### 2. xcap 截图完整性 ✅ **通过（方法 A 主力）**
- **关键结论（架构性）**：
  - **方法 A（`w.capture_image()` 窗口直捕）= 抓窗口自身帧缓冲** → 即使被其他应用遮挡也能拿完整界面，VLM 输入必须干净。
  - **方法 C（Monitor 全屏 + 裁切）= 截屏后裁剪** → 窗口被挡则挡的部分去不掉，**仅作兜底**。
- **DPI 修复闭环**：
  1. 原始 629×658 截断（无 DPI 感知）→ 加 `enigo::set_dpi_awareness()` → 暴涨到 1091×724（覆盖率 99%）。
  2. 中途误试过 ×sf 坐标换算（导致 498×1090 狭长条），已废弃——`set_dpi_awareness` 后窗口坐标已对齐物理像素，无需再乘。
  3. 现逻辑：**方法 A 覆盖率 >85% 即直接采用**；否则退回方法 C（原始坐标不乘 sf）。
- [x] 实测：`mc_capture.png` = 1091×724，MC 画面完整、文字清晰，供 VLM 足够。
- [x] 用户确认：方法 A 即使被其他应用遮挡也能获取完整界面（优于方法 C）。

### 3. 输入焦点与坐标一致性 ✅ **通过（实测 2026-07-12）**
- [x] `coord` 模式：enigo `move_mouse(x,y,Coordinate::Abs)` 能把光标移到窗口中心/左上1/4/右下3/4
- [x] 用户确认：**光标能移动且偏差人眼不可辨**（< 几像素）→ 绝对坐标映射无粗误差，够 VLM 点击用
- [x] **关键行为约束（MC Java 版窗口化）**：OS 光标移出 MC 窗口 → MC 自动暂停弹菜单
  - 含义：agent 所有 UI 点击目标必须 **严格落在窗口内**，且需留安全边距（如 10~20px），避免误触边缘导致暂停
  - 应对：Phase 1 点击前对目标坐标做窗口内钳制（clamp）；绝不主动把光标移出窗口
  - 注：MC 暂停本身可用 ESC 键主动触发，不必靠移出光标
